### How It Works ⚙️

The [Monthly GitHub Digest](.github/workflows/run_digest.yaml) workflow runs on the 1st of each month at 00:00 UTC. It runs [`digest.py`](digest.py), which collects the previous month's opened issues, closed issues and merged pull requests for every project above, and commits the result as `github_digest_<Month>_<Year>.md`.

- **Run it manually:** go to **Actions → Monthly GitHub Digest → Run workflow**. A manual run regenerates the digest for the previous calendar month and overwrites the existing file for that month.
- **Add or remove a project:** edit the `repos` list in [`digest.py`](digest.py) and update the list above.
- **Authentication:** the workflow uses the built-in `GITHUB_TOKEN` that GitHub Actions provides automatically. Nothing needs to be configured, and no personal access token should be added. Without a token, GitHub allows only 60 API requests per hour, which is not enough for this many projects.
- **Errors:** if the GitHub API returns an error (for example a rate limit), the run fails instead of producing an incomplete digest. A project that no longer exists is skipped with a warning in the run log.

To run it locally: `pip install requests`, then `GITHUB_TOKEN=$(gh auth token) python digest.py`.
